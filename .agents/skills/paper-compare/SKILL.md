# paper-compare · 有条件的技术综合

输入：用户焦点、固定论文范围、已接受单篇接口/机制/命题及决定性双端来源。输出：一份 comparison 候选和真实知识影响线索；正式目录仍为 `专题/`。不是逐篇摘要或跨协议排行榜。

| 本轮 | 只加载的指南 | 本轮结果 |
|---|---|---|
| M1 | [alignment](references/alignment.md) | 共同问题、分析单位、不变量与必要接口 |
| M2 | [evolution](references/evolution.md) | 同情境路径、技术关系、瓶颈/改变/新代价 |
| M3 | [evidence](references/evidence.md) | 逐命题可比性、争议、选择/反转与区分观察 |
| M4 | [composition](references/composition.md) | 连贯对比候选与双端强判断回查 |

一位独立比较 owner 按 [自主执行契约](../paper/references/unit-owner.md) 完成 M1→M4，内部逐阶段保存/核对/返工，只交最终结果。默认直接读取单篇最终接口与必要双端来源，不加载所有中间轮正文；缺接口再定向补证，不由父会话逐轮转述。

共同情境是机制分析，须标教学推演；性能优劣/因果结论必须另核数据、协议、预算和统计支持。技术演变既讲旧方案为何合理与瓶颈条件，又讲新接口改变、新能力/成本/假设；没有双端依据就保留平行、分叉或未知，不替作者造动机。

成文才读 [comparison 模板](assets/comparison.md)、[写作](../paper/references/writing.md)及 [Obsidian](../paper/references/obsidian.md)。已有合适专题时可更新相应比较区块或链接独立对比，不机械再建同题页。协调者统一知识影响与审阅；作者不并发改共同正式页。
