# R1 · 第一遍：建立问题模型

本轮只做 B1，不写完整方法/实验/第三遍或最终论文。读固定版本的标题、摘要、引言、结构、结论及决定性的图/表入口；实际读到的窗口登记覆盖。

## 动作

1. 明确任务、对象、输入/输出及约束；作者声称解决什么，主要设计为何可能回答它。
2. 用 5C 组织定位：Category 类别与读法、Context 直接相关前驱/平行工作、Correctness 暂需核的假设、Contributions 作者贡献声称、Clarity 当前理解/不清楚处。把宽泛疑问改成论文特有、后两遍可以用来源回答或裁决的问题；这里只建问题模型，不能凭一遍宣布正确性。
3. 按“回答后会改变哪项贡献解释、采用条件或复现选择”确定中心问题及优先级，绑定方法/定义、学习/证明和证据入口；不按模块平均分配篇幅或凑问题数。对一般模块先闭合必要接口，对中心机制保留深入核证与反证任务。
4. 确定直接前驱与最强替代的身份、对应贡献和待核原文入口，第二遍核实际机制后才作创新比较；材料缺失就限定已读范围。方向查全另走追溯，不批量建卡。若原文有能贯穿中心机制的实际实例，登记位置，优先接续它。

## 交付与停止

交付短科学结果：任务与约束、贡献声称及来源、5C 的具体内容、能改变理解的疑问与下轮入口、已读范围和关键未知。没有证据的设计理解标暂定。用户问题如何影响后续阅读写清。

接受条件：研究对象固定、问题具体、声称未升为事实，每个重要疑问有可读入口或真实材料缺口。保存本轮结果并在 owner 内回查、自查或局部复核；登记接受后才加载 R2a。默认不向父会话交阶段正文。
