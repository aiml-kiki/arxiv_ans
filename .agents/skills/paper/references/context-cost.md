# 上下文成本与证据交接（按需加载）

只在评估委派、R4 成稿隔离、主动 owner 交接或成本复盘时加载。科学质量门先通过；缓存输入仍计入全树 token。`resource_reads` 的字节量只说明显式资源交付，不能代替模型用量。

## 先量什么

按同一固定论文版本、问题、来源范围和验收门，分别记录根、owner 的 R1/R2/R3/R4、定位/成稿/高风险助手、独立审阅的响应数、输入（含缓存）、缓存输入、输出、返工轮次和耗时。阶段归属用实际阶段开始/结束事件或响应元数据；跨阶段/跨任务响应标为未归属，不按字符串时间或猜测分摊。响应动作只用工具名及调用 ID 标注，不能把整次响应的重复上下文归因于工具；不存命令参数、prompt 或思维过程。`usage` 只报告实际可见回执；全树缺线程或边界不可比时不报节省率。先看各响应输入是否随上下文累积，再检查文件重读量：二者是不同原因。

`usage.action_profile` 汇总与等待/状态/委派等动作关联的整次响应；`context_growth` 对同一线程的相邻响应窗口给实际输入均值变化。后者不控制交接：阶段混合、缓存与不同任务可造成波动，预测还须加新实例启动、核源、复核、返工、旧实例停止及估计误差。实际 model/effort 未由宿主回执暴露时保留 null。

## 最小证据索引

只有同一页段会跨阶段、跨助手或交接复用，且预计减少的重复输入超过建索引及定向核证成本时才建。索引是 `.research/work/<run>/units/<unit>/evidence-index.json`，每项仅含 ID、固定 manifest/原文字节哈希、物理页、解析页内起止位置、片段哈希、用途；**不复制片段或判断正文**。可用 `research.py evidence build --run … --unit … --spec <窗口列表.json>` 建立、`evidence get --run … --unit … --ids id1,id2` 定向取片段。选段由阅读者负责，脚本只核哈希和位置；图、公式、关键表及会改变结论的冲突仍看原页并由 owner 复核。单次使用或只在同一已读上下文使用时，直接用 `source pages`，不增加索引。

助手收到唯一问题、必要科学前提、证据 ID/页码、接受条件及独占结果路径；只取所需 ID，不重读整份 PDF、全部科学稿或父历史。结果返回结论、页码、限制和可区分观察；owner 定向核决策性原文后写入同一科学稿。索引失效就重建或直接回源，不让旧哈希指向新内容。

## 委派与物理交接

先估本人与助手各自后续响应的**完整树**输入/输出、缓存、启动、检索、核证、返工和等待。R4 初稿可以隔离，但只有预计净节省且科学责任仍在 owner 时才触发；格式整理、来源定位优先脚本或低档助手，中心机制冲突才用高档助手。委派失败或审阅不合格时，成本连返工一并记录，不能只算成功分支。

在已接受 R1/R2/R3 边界，用最近响应的输入增长估计剩余执行：比较旧实例后续全树成本，与新实例启动、短状态、证据核验、重复理解、旧实例停止、审阅和预期返工之和。只有预测净收益明显超过样本波动与估计误差才交接；不要求先试局部助手。交接前保存固定版本、接受 checkpoint、必要证据 ID、未解问题、用户约束和下一轮；真实停止旧实例并登记 interrupt/handover，新 owner 复核中心来源后接管唯一责任。不得在执行中的科学轮换 owner，也不得同时写同一候选。一次交接不证明节省，仍须同范围实测。

## 判定顺序

先独立审科学门和展示门；不通过则修复并把返工计入。再比较完整树实际 token，随后看耗时与复杂度。把优化逐项隔离：先减少根会话例行唤醒，再比较原阶段与 `pass_trial` 的机械 checkpoint、继续 owner 与有核源的物理交接、本人 R4 与隔离初稿；每个变体保留来源、科学问题和质量门。一次只改一个可归因变量。三遍阅读顺序、关键原页核证和首次完整独立审阅不能缩减。`pass_trial` 只有逐项记录能恢复、质量不降且完整树实测有净收益才成为默认，否则退回原阶段模式。

完整验收至少覆盖三种结构不同的固定版本论文，各做同范围精读 A/B；随后用真实对比、追溯、知识任务验证可迁移部分。盲审者不知道旧新方案归属，依据原页核机制可重构、竞争解释、证据边界和展示质量；对比分别审技术演变与条件选择，追溯审来源链与覆盖，知识审可迁移机制和适用边界。缺来源或科学质量失败的稿不能用低 token 抵消。计入根、owner、助手、审阅及返工的实际输入（含缓存）、输出、耗时；不可见 usage、不同根历史或范围差异明列缺测，不报因果节省率或四倍达成。只推广质量达标且实测净收益的分项。
