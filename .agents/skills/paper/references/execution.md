# 主会话：一次启动完整单元

委派或恢复时加载本文件；[路由](../agents/routing.yaml)用于选择请求档位，当前工具定义决定实际能力。脚本不启动代理。

## 启动与等待

1. 固定问题、来源版本、用户约束、目标及依赖；计划默认 `autonomy: unit`。每个正式目标指定唯一候选写者。
2. 用 `runtime configure --run <run> --event <宿主能力.json>` 启动时登记真实宿主能力：创建/嵌套委派、隔离参数、可用 model/effort、角色、活跃及打开线程容量、关闭、usage、自动/主动压缩与恢复。未暴露的能力记 unavailable，配置偏好不当实际事实。当前接口全树活跃容量为 4（含根）；以后运行重新核对。首次 configure 或需要管理助手事件时按需读 [宿主事件字段](host-runtime.md)，不读取 runtime 实现。
3. 每篇完整精读一位 owner，比较/追溯/确有增量的集中知识工作按完整单元启动。精读和常规比较先以中档为先验；开放追溯/复杂综合按已见难度在中/高档间选择。筛选和知识查重先脚本，必要时才低档局部助手。综合可验证性、中心结论风险、上下文依赖与全树成本，记录具体请求档位和理由；配置映射不能证明宿主执行了该模型。容量允许时默认两位 owner 并发；关键科学复核需要助手名额时按风险调整启动顺序。`fork_turns: none`，只给 run/unit、库根、能力入口、问题/用途、固定来源、独占草稿/目标、用户约束、能力及预算边界，不继承父全文或加载整套指南。
4. 真正 spawn 后登记 `workflow start-owner --event`。绑定只证明代理身份与启动事实，科学阶段先 preparing；初始任务说明登记时差由脚本有限等待处理。本人 owner 自主完成所有适用阶段，不让其只做 R1 就结束。
5. 绑定 owner 后根进入 `WAIT_OWNER`：只处理 `owner_final`、`actionable_exception`、`user_decision_required`，以及用户主动要求状态或宿主确认的故障/停滞告警。用当前宿主和会话规则允许的有界事件等待；单纯超时只续等，不读 `workflow status`、`list_agents`、阶段稿或助手消息，也不向已运行 owner 续派。普通阶段完成只留在 unit 内，不向根发进度消息。`owner_final` 至少给候选路径与哈希、固定来源/版本、少量结论与关键未决、核验和 usage 引用；根收到后才启动独立终审及下游单元。异常报告具体阻碍和所需动作。`list_agents` 只用于真实容量、异常和恢复判断；用户问进度时才读 `workflow status` 简包。等待接口仍可能在超时或新消息时唤醒，skill 不能保证零根回合；真正只在完成时唤醒需要宿主支持异步完成回调，不能伪称已实现。

长对话的可选独立任务入口只在用户**明确选择新任务**时使用；新任务从固定来源、目标和约束建立短启动封套。普通调用留在当前会话，不静默创建用户可见任务或把既有任务伪装成隔离执行。两种入口的根用量分开计量，不能把新任务的短历史收益误归因于科学流程。

## 容量与边界

owner 按已授权范围自主创建有收益的局部助手，由本人接收、核证、整合。根 0→owner 1→助手 2 是项目最大委派深度，助手默认不再委派；不是官方 `agents.max_depth` 配置。全树所有活跃 owner/helper 计入容量，打开线程数另计；工具未提供关闭时不假装已释放打开额度。

在真实 spawn 前预留容量，成功后绑定回执，已绑定助手真实结束/失败后 complete；cancel 仅释放未绑定的预留。容量不足时优先处理会改变中心结论的复核；低风险局部工作交脚本/owner 或等名额，必要时延后启动另一 owner，不为维持两篇并行抢占关键复核。共同 workflow 事务由脚本锁串行；各 owner 只写本人科学稿/独占候选，助手只写本人结果区。正式页、索引和共享候选整合由单写者负责。

## 恢复与降级

补源是输入事务，不是物理交接。append/replace/changed-premise 按 [owner 契约](unit-owner.md)暂停/准备及重开实际受影响边界。在**已接受**的 R1/R2/R3 边界比较继续执行、局部委派和物理交接的预计全树成本；若最近实际响应增长表明交接净收益明显高于估计误差，可直接交接，无须先试局部助手。先真实停止旧实例并登记 interrupt，再交给新隔离实例。交接包只给固定版本、接受判断、短证据索引、关键未知、用户约束和下一阶段；新 owner 定向核关键原文并登记 handover/adopt，接管唯一科学责任与候选写入权。缺真实 usage 时不凭字符数强制交接；非主动中断优先恢复同一 owner。未完成的科学轮不以交接伪装成接受。

用户要求单代理、工具/额度失效或交接成本过高时，记录具体原因并使用受支持的执行方式降级；保留已接受判断、来源和用户约束。跨单元冲突、用户缺失信息、权限或平台故障才报异常：阻碍、完成范围、恢复入口、所需决定。主会话收最终候选路径/绑定版本、少量结论、关键未决、检查/usage 引用，助手及阶段报告不向上转发。

已绑定代理确需主会话接手时，先真实中断并登记 interrupt，再登记 `dispatch mode:main` 的实际执行、具体降级原因和交接；原 unit 保留已接受轮次，主会话按当前边界使用 step/checkpoint/report，执行归属记真实根 ID，不冒充原 owner。主会话不能与未停止的原 owner 同写候选。

## 计量与最终门

线程别名须与 session 元数据核验：root 不得有父线程，代理的 `thread_spawn.agent_path` 须匹配；guardian 等宿主辅助线程不得替代根。缺真实根回执时只报已观察子树，不能认证全树或节省率。

评估时按需加载 [上下文成本与证据交接](context-cost.md)，先判科学质量，再核完整树成本和未归属用量。`usage --run` 的 `stage_profile` 仅把实际 begin→checkpoint 或 begin→真实 interrupt/awaiting-input 窗口内可识别响应归入阶段；准备、过渡、暂停间隙、恢复和无时间回执保持未归属。`action_profile` 从同一 Codex JSONL 中相邻工具名标注等待/状态/委派等响应，只代表整次响应的关联动作，不能把其输入 token 当作工具本身的因果成本；未匹配的保留未归属，不读取或保存工具参数。

启动封套和后续控制包使用软预算，不能截断必要科学材料。usage 在既有工具批次或离线汇总采集，不新增模型轮询；逐响应、全树汇总和累计快照须区分并去重，cached 输入计入 token，reasoning 是 output 子项时不重复相加。不可见数据记 unavailable，字符量仅代理指标，不报真实 token 或节省率。离线聚合用 `usage --input <选定本地JSON或JSONL> --scope-manifest <范围.json> --output <库根相对计量.json> [--baseline <同范围完整基线.json>]`；input 可重复，范围声明 `evaluation_scope/expected_threads/full_tree`，只保存计量元数据，不将会话正文复制到库或远端。新版 Codex JSONL 若有逐响应 `token_usage_record`，优先使用它并核对同 turn 累计值，避免与 `token_count` 快照重复相加；同一桌面线程含多任务时用 `selected_turn_ids` 映射选择真实 turn，并用 `actor_thread_ids` 把 workflow 代理 ID 绑定到实际线程 ID。旧 JSONL 的首个 `total_token_usage` 是线程累计快照，可能包含该线程此前工作；选择完整隔离线程作为评估范围，或用正确观测边界取得增量。不能直接将首个累计量归为当前 run/stage 的精确用量，无法归属时保留缺测/范围限制。缺实时遥测时预算是提示，不能声称硬拦截每次生成。

当前桌面工具没有主动压缩接口；自动压缩的配置或 API 能力不证明本会话已加载/发生。压缩后由 owner 读短科学状态及当前指南定向补证。写状态文件不移除已有消息；只有成本理由、已接受边界、真实停止与新实例核证俱全时才做物理交接，不能把阶段重启本身报作节省。

使用 `usage --run` 汇总时同时核真实 owner、助手历史回执及根 ID；full_tree 范围遗漏已登记实例会拒绝成本验收。此校验仍不能证明未登记的宿主调用不存在，实际全树必须由宿主观察补齐。

首次完整独立审阅默认请求全新上下文的中档审阅者，按能力质量门核贡献/机制、必要细节、证据/边界及双端关系/条件选择；只有难判且可能改变中心结论的争议才另请高档定向复核。局部返工只复核 diff 与受影响原页，跨中心判断的返工重做完整审阅。普通缺项返原 owner；所有适用科学边界、唯一候选责任、实际最终科学复核、同组机械检查及授权通过后才发布。详见 [审阅协议](review-publish.md)。成本与质量分开验收，实施本身不证明四倍降耗。
