# 原生 Obsidian 的展示与交互

四类正文共用这一份规则，成文/审阅时加载。正式目录为 `论文/`、`知识/`、`专题/`；对比与专题用 `kind` 区分。Markdown 是语义事实源，生成索引、Bases 和 Canvas 不是另一套正文。

## 可读正文

- 属性用扁平值或列表，保留 `id`、`kind`、`tags`、`analysis`、`updated`，论文加固定 `source`/`version`；`analysis` 只表示分析程度，`updated` 表示分析更新日期，纯排版不更新它。复杂 claim 数组、评分和嵌套关系写到正文/派生记录，不塞 Properties。
- 结论先行，长页给按“理解机制/核验证据/选择/继续研究”命名的少量标题入口。层次清楚，其余页内移动交原生大纲；不另堆完整目录。
- 公式使用 `$...$`/`$$...$$`，邻近定义符号、形状、单位与作用。短表并列共同维度，长推理放表外。表内 Wiki 别名管道须转义，例如 `[[知识/实际概念\|补前提]]`；表外仍用 `|`。长来源说明放表下，短来源入口可留表内。不要用 HTML 表格或 `<details>` 替代原生结构。
- 原生 `[!abstract]` 给简短概要/导航，`[!example]` 标教学例子，`[!warning]` 标实质误读风险/限制，`[!question]` 标真实未解问题；`[!note]-` 只折叠非主线。并非每章都需要提示块。关键接口、配置行为、限制与决定性负面证据不能藏起。
- 方法框架默认短行 `text` 树；围栏中的 Wiki 不可点击，导航和来源链接放图后。并行/反馈确实更适合时才用原生 Mermaid，不默认画两份。

## 链接与锚点

Wiki 按实际库根和真实文件/标题/块生成；首次出现先解释再链接，并交代关系。原生反链负责发现引用，不手工抄一份反链正文。少量短定义/证据可以块嵌入；不嵌整页、不循环嵌入。以下只示意，发布须替换真实目标：

```markdown
[[知识/实际概念#适用条件|理解这个前提]]
[[论文/实际论文#^claim-work-boundary|核对该判断的条件]]
[[附件/实际工作/实际版本.pdf#page=8|原文 PDF 第 8 页]]
![[知识/实际概念#^claim-concept-definition]]
```

稳定 ID 用 ASCII 字母、数字和连字符，普通段落末尾为 `...。 ^claim-work-boundary`，caret 前有空格。保留既有 ID，不因重排改名，不用 CSS 隐藏正常显示。列表/callout 整块锚定遵循其原生规则；不能把引用内一行 ID 当整块命题。**已注册判断及紧邻字段必须保持普通 Markdown 段落，不移入 callout、列表或表格；重排不缩小被引用段落的范围**。未注册教学例子可放 example；不要再复制一份核心判断当装饰性摘要。

图旁解释轴、单位、对象、操作和支持范围；PDF `#page=` 指真实 PDF 物理页，正文印刷页与其分开。附件固定版本；不拼外部绝对文件路径作为 Wiki。

## 原生视图和讨论

Bases 总视图按正式目录筛选，排除 `审阅/` 和内部草稿；细分对比/专题时用显式 `kind`，缺失 kind 的旧页仍保留在目录总视图和未分类视图，不按文件名猜。`file.mtime` 标“最近编辑”，`updated` 标“分析更新日期”，`analysis` 标“分析程度”；都不表示用户读过或掌握。可复用配置见 [资料库视图模板](../assets/library.base)，视图名已有入链时保留。首页以定位/任务入口→最近编辑→分类入口→批注帮助→折叠说明排列，不重复全文手册。

Canvas/Mermaid 中的语义关系必须先有 Markdown 依据，引用事实图与技术推断图分开。Canvas 可选，确认实际库根；多库场景使用唯一 Wiki 名/生成文本卡，未经实际界面核查不称点击或渲染已通过。

用户阅读路径为：一分钟判断→方法→证据→可迁移知识→对比/专题→未解问题。讨论区保留“用户原话与我的笔记”，分析另列；没有用户内容时留一条可替换编辑提示。稳定问题块用于真实问题，方便后续直接指定。首页提供可复制的续读句式；代码块、链接或用户勾选框都不构成运行指令，默认不增加测验和掌握评分。编辑态可借页面预览查看链接内容，阅读态可点标题/块/PDF 回查。

## 候选与正式页

内部 `.research/drafts` 不保证 Obsidian 可见。按 [审阅协议](review-publish.md) 生成 `审阅/<提案>/` 展示投影、总览和 diff；候选保持 kind 和稳定块。同组修改目标映射到同组候选，未改目标仍连正式页，来源仍连附件。正式索引/Bases 排除待审目录。

用户在候选上编辑后须读回合并、更新 diff，不静默覆盖。发布转换回正式目标，不能遗留审阅依赖；检查出链及被改标题/块的既有入链。内部任务包无需全部公开。没有实际 Obsidian 界面检查时报告结构检查范围，不能冒称界面验收。
