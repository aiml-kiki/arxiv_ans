# 正文判断与证据绑定

当前轮只读所需部分。主贡献、关键假设、决定性正负结果及跨篇选择才需要显式登记；普通解释、术语和导航不登记。结构不能代替原文核验。

## 命题字段

- 正式 Markdown 是唯一可编辑语义源；派生索引从正文重建，不维护另一份判断文本。只有 `论文/知识/专题` 进入正式索引。
- 判断直接写成连贯正文：**观察到了什么 → 为什么支持这个结论 → 在什么条件成立、不能推出什么**。条件和理由融入论述，不另设可见或折叠的判断记录。
- 核心段尾保留 `空格 + ^ASCII块ID`。保留已有 ID、引用范围、标题入链和用户原话；不为排版改名、移入提示块或复用 ID。
- 必要登记用紧邻核心段落的单行 `<!-- paper-object {...} -->`。注释只保存类别、状态、技术定位和来源身份；范围、理由、假设、问题进展等**指向同页正文块**，禁止在注释复制科学解释。普通注释、代码示例、引用和其他提示块不是登记。
- 证据指向正文中实际出现的来源链接及解释；不能在注释另存一份链接或证据摘要。正文不充分时先补正文，再绑定；不能把未知包装成支持。
- 旧普通字段和旧折叠记录仍可读取，历史快照不改；新增稿只生成正文绑定。迁移旧记录必须核对正文覆盖，不以隐藏字段完成迁移。

`kind`：`命题 / 关系 / 未解问题 / 知识更新`。非分类解释写为 `{"block":"本页稳定ID"}`，解析器从唯一可见普通段落读取。命题必需 `判断类型`、`提出者`、`范围`、`裁决`（status + reason）及至少一条 evidence；可选 `假设`、`区分观察` 和 `依赖`。作者声称、原文观察和分析者推断仍在正文措辞中区分，分类注释不替代说明。

## 命题示例

以下仅演示语法，不代表实际已核证据；正式稿必须换真实来源与定位。

```markdown
固定参数和历史前缀时，候选无关状态可复用。状态定义不含候选输入，但不能由此推出跨参数更新仍然等价；原文没有给出刷新后的验证。[[附件/paper-example/v1.pdf#page=8|p.8 §3.2 状态定义]]。 ^c-state
<!-- paper-object {"kind":"命题","fields":{"判断类型":"机制","提出者":"分析者","范围":{"block":"c-state"},"裁决":{"status":"有条件支持","reason":{"block":"c-state"}}},"source":{"id":"paper-example","version":"v1","verification":"定位已核"},"evidence":[{"relation":"支持","block":"c-state","link":0,"location":"PDF p.8 §3.2"}]} -->
```

`判断类型` 可为机制/经验结果/理论/实现/跨篇选择/假设；裁决可为支持/有条件支持/证据不足/相反证据/原文未知。字段可指核心段自身或其他已有正文段，不为每个字段新造段落；注释紧邻核心段，中间仅空行。

## 身份与固定证据

- `source` 的 `id/version` 必须与真实 source manifest 一致；`verification` 为 `定位已核/未核`。来源版本有多个全文哈希时给 `sha256` 消歧。PDF、HTML、补充材料、代码分别固定真实版本/commit 与全文哈希。
- `evidence` 每项为 `relation`（支持/限制/反驳/背景）、`block`（承载依据和解释的正文段）、`link`（该段 Wiki 或 HTTPS Markdown 链接按出现顺序从0计数，默认0）、`location`（实际 PDF物理页/节/表图/公式/代码位置）。不能只写“全文”。机械绑定只核定位和身份，不证明支持关系成立。
- 共同 source 只在该对象内使用。证据有不同来源/版本时用完整 `source` 覆盖，必须独立给 id/version/verification，不能继承另一来源核验或哈希。比较关系必须保存双端依据。
- 同一段中的同一来源链接可供支持与限制共用；支持/限制是两种语义关系，不需要显示两次同一链接。不同段承担不同论证时允许再次链接，不机械设数量上限。
- PDF 链接指固定附件和真实 `#page=`；网页/代码用已固定材料的官方 HTTPS 回查入口。正文就地说明关键数字的单位、分母、协议、预算和统计限制，不登记全部实验成绩。
- 分析完成、证据定位、独立复现是不同状态；`定位已核` 不代表复现或用户掌握。

## 关系字段

所有自然语言判断都先写正文，注释只绑定。技术引用定位字段使用 `论文/名称#^块ID` 等正式路径，不在注释放另一份 Wiki 链接；正文只保留有阅读价值的必要前提、证据或下一步链接。

| 类型 | fields 必需项 | 解释与限制 |
|---|---|---|
| 关系 | 源、目标、关系类型、归属、范围（正文定位） | 源/目标各一个已注册块；普通 Wiki 不是关系。确认承继/替代/分叉/组合须至少两端 evidence |
| 未解问题 | 问题状态、范围、竞争解释、区分观察、进展（后四项正文定位）、参与命题（定位列表） | 当前缺口、竞争解释和如何区分直接可见，不另复制问题卡 |
| 知识更新 | 增量类型、旧判断、新判断、处理决定（后三项正文定位） | 实际变化须固定证据，受影响可列块定位；重要旧→新留持久记录，当前知识页讲清现行理解 |

关系类型：导航/前置/实例/证据支持/依赖/限制/反例/引用/承继/替代/分叉/组合。归属：作者明说/分析者推断/待核验线索；引用与时间先后不证明技术承继。

问题状态和更新选择见 [增量协议](protocol-update.md)。依赖/参与命题/受影响可为字符串或定位列表；并列支持不等于必要前提，不取证据数量、最小值或平均值自动裁决。

## 旧稿迁移

先逐项把旧记录独有的范围、理由、反例和未披露后果融入正文；已有内容只绑定，不重复添加。提供 `块ID→正文绑定` JSON 后使用：

```sh
uv run python .agents/skills/paper/scripts/research.py --root . derive format --input <已核稿.md> --bindings .research/work/<run>/body-bindings.json --output .research/drafts/<run>/body.md
```

工具拒绝缺定位、丢对象、改变类别/裁决/关系或固定证据身份，输出只到新草稿。解释和链接改指正文须实际审阅，**不宣称自动语义等价**。科学实质修改继续走原有科学轮次及绑定最终快照的审阅门。正式页不批量迁移。
